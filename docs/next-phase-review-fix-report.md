另以實際 library store、mock IPC 做追加前端測試：後端資料改變本身不會立刻改前端快照；`refresh()` 後已讀篩選與繼續閱讀候選跟隨新狀態。`App.vue:43–50` 返回書庫會先 flush、再 refresh，register 匯入及管理操作也有刷新入口。這確認了資料庫更新與前端刷新是兩個時間點，並未把 mock 當原生整合驗收。

成功／失敗與保存前後的後端狀態已由測試核對；實際 UI 等待、渲染、原生 IPC 時序仍屬下列實機待驗項目。既有「交易失敗不替換目前書籍」案例本次仍通過，追加失敗開書案例則從空 reader 驗證。
